# PROJECT.md — УПД Сервис (v2)

Живой документ проекта: цель, архитектура, решения, план. Правится по ходу работы.
Технические «нельзя ломать» правила XML — в `CLAUDE.md`.

## 1. Цель
Бесплатно превращать PDF бухгалтерских документов (текстовые и сканы) в XML ФНС
`ON_NSCHFDOPPR` v5.03 для загрузки в 1С. Пользователь загружает PDF → видит превью и
распознанные поля → правит → скачивает XML (windows-1251).

Ограничения: бесплатно (Groq free tier), без GPU, один пользователь / малая команда,
запуск локально или на небольшом сервере.

## 2. Почему v2
- Сервис сломался из-за снятия моделей Groq (qwen3.6-27b отключена 14.09.2026). Модели
  будут сниматься и дальше → нужна **цепочка моделей с автоматическим fallback**, а не одна
  жёстко прошитая.
- Ошибки распознавания были «глухими» (без причины) → нужны **логи и понятные ошибки**.
- Нет тестов, нет CLI → нельзя проверить распознавание без браузера.
- Видится только 1-я страница; сервис не умеет многостраничные документы.
- Мусор в репозитории (`service.py` на Gemini, `upd_mapper.py` — дубль плагина).

## 3. Принципы
1. Конфигурация только через `.env` (читается автоматически), ключей в коде нет.
2. Любая внешняя ошибка (Groq: 404 модель, 429 лимит, 401 ключ, таймаут) → понятное
   сообщение пользователю + полный traceback в лог.
3. Тип документа = плагин. Новый тип — один файл, остальное не трогаем.
4. Правила XML из `CLAUDE.md` покрыты тестами: сломать их незаметно нельзя.
5. Распознавание проверяемо без UI: `python -m upd_service.cli файл.pdf`.

## 4. Структура
```
upd_service/
  config.py        # .env, модели, таймауты, лимиты
  pdf.py           # текст, рендер страниц в JPEG, превью, поворот
  llm.py           # Groq: retry на 429/5xx, fallback по цепочке моделей, parse_json_safe
  pipeline.py      # PDF → тип → промпт → LLM → нормализация → dict
  normalize.py     # чистка ИНН/КПП/сумм/дат, сверка математики (серверная)
  registry.py      # автозагрузка плагинов
  doc_types/       # upd.py, schf.py, (torg12.py, akt.py — позже)
  api.py           # FastAPI-роуты (тонкие)
  cli.py           # распознать PDF из терминала, вывести JSON/XML
  static/index.html
tests/             # pytest: XML-правила, normalize, parse_json_safe, pipeline с mock LLM
samples/           # эталонные PDF/XML (не в git, если конфиденциальны)
.env.example  requirements.txt  PROJECT.md  CLAUDE.md  README.md
```
Запуск: `uvicorn upd_service.api:app --port 8000`.

## 5. Распознавание
- Текстовый PDF → текст страниц в текстовую модель. Скан → картинки страниц в vision-модель.
- Цепочка моделей в `.env`: `GROQ_MODELS=qwen/qwen3.8-27b,openai/gpt-oss-120b`
  (vision — отдельный список). При 404/«model decommissioned» берём следующую.
- Многостраничность: страницы со ввода склеиваем; таблицу товаров с нескольких страниц
  объединяем (фаза 3).
- Ответ модели всегда проходит `parse_json_safe` + `normalize` (ИНН 10, КПП 9, суммы с
  точкой, даты ДД.ММ.ГГГГ), затем серверная сверка математики → `meta.warnings`.

## 6. API (сохраняем совместимость с фронтом)
`POST /api/recognize`, `POST /api/preview-xml`, `POST /api/generate-xml`,
`POST /api/encode-xml`, `GET /api/doc-types`, `GET /api/health` (проверяет ключ и модели
из цепочки: какая жива, какая снята).

## 8. Открытые вопросы
- Рабочий экземпляр — Ubuntu-сервер, ключ задан там. Версия health старого кода проверяла только текстовую модель, а сканы идут в vision-модель: на сервере в `.env` может стоять снятая `GROQ_VISION_MODEL`. Нужен текст ошибки с сервера (`journalctl`/консоль uvicorn).
- Нужны эталонные файлы в `samples/`.
- Лимиты free tier на Qwen 3.8 (запросы/токены в мин.) — замерить на реальных сканах.

## 9. Окружения
- 403 Forbidden от Groq на сервере (получено 2026-10-10): блок IP/страны → `GROQ_PROXY` в `.env`, либо модель не включена в Settings → Limits консоли Groq.
- Разработка: macOS, `.venv`, ключ в локальном `.env` (не в git).
- Прод: Ubuntu, ключ и модели в `.env` на сервере. Деплой: `git pull`, `pip install -r requirements.txt`, перезапуск сервиса.
